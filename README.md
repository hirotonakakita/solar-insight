# Solar Insight — 公開データと個人観測で試す太陽画像解析・フレア予測

太陽フレア予測の研究を参考に、公開観測データからモデルを作り、自分の撮影画像で予測を試した個人研究です。夏休みの自由研究「Xクラスフレアを観測する」をきっかけに、専門機関の予測の考え方を個人の機材と公開データでどこまで実践できるかを探りました。

作者は医療機関への情報提供・医療システムの導入支援に携わってきました。本プロジェクトは、課題設定、データ選定、生成AIへの実装指示、出力確認を通じて、AI・機械学習の流れと限界を学んだ事例です。医療AIの開発・導入実績を示すものではありません。**コードはすべてGPTを使って作成しています。**

## 目的と到達点

目指した流れは「過去の公開データで学習 → 自分の太陽画像で推論 → 観測中のHα撮影の判断に利用 → Xクラスフレアを撮影」です。Xクラスを主目標、Mクラスを参考情報として選びました。

| 項目 | 到達点 |
|---|---|
| 黒点画像解析 | 黒点・群候補の検出、相対数Rの算出、注釈画像の作成 |
| 画像＋数値モデル | 試作と推論を実施。本人の使用では観測判断に役立つ予測精度に至らなかった |
| 観測支援 | 解析画像を、群の大きさ・密集・配置・変化を見る補助として利用。有用性は本人の感触で、定量評価ではない |
| 実際の観測 | 本人の経験的判断でHα撮影に切り替え、Mクラスを2回撮影。GOESデータと照合。モデルの成果には含めない |
| Xクラス撮影 | 達成せず。本人の観測時間中にはMクラスのみ発生したとの記録・説明 |
| 発展案 | SDO多波長・磁場画像の時系列とGOES記録を使うモデルを構想。データ収集・整備の規模と計算負荷への懸念から未着手 |

予測精度の達成だけでなく、実データと個人観測で試し、データの違い、評価方法、運用上の制約を把握することを研究の成果としています。現在の整理版は、画像解析を実行できるCLIと、任意の実験的推論コードを提供します。

## 観測・データの流れ

Seestarで太陽動画を撮影 → 手動でAutoStakkertによりスタッキング → 生成画像をツールで解析・推論、という手順でした。自動で撮影・予測を更新する運用は実現していません。

撮影時間は天候によって変わり、可能な範囲で長く撮影しました。AutoStakkertの設定は毎回固定していましたが、具体的な設定値の記録はありません。本人の記憶では太陽画像向けのデフォルト設定です。

旧予測ログは14件で、日時、黒点数、群数、R、X/M出力を保存しています。日時は**元動画の撮影開始時刻（JST）**です。撮影終了時刻・動画の長さ・解析実行時刻は含まれません。旧ログの出力は較正済みの発生確率とは扱いません。このログは現在のCLIのCSV形式とは異なります。

学習には過去約10年の国立天文台の公開画像とNOAAのフレア記録を利用したとの本人の説明があります。期間は太陽活動周期をおおむねカバーし、両方のデータがそろう範囲を意識して本人が決定しました。対象期間と実際に学習へ使えた件数は別で、確認できた結合CSVは1,651行です。自分のSeestar画像は推論の試用に使いました。

## 実行

Python 3.11以上を使用します。プロジェクトフォルダで実行してください。

```sh
python -m venv .venv
# Windowsのコマンドプロンプト: .venv\Scripts\activate.bat
# macOS/Linux: source .venv/bin/activate
python -m pip install -e .
solar-insight sample_data/synthetic_sun.png --output-dir outputs
python -m unittest discover -s tests
```

実画像も同じコマンドで渡せます。ファイル名に撮影日時がなくても解析できます。検出前後の比較PNG、黒点候補の座標CSV、群数・候補数・相対数のJSONを出力します。

```sh
solar-insight sample_data/20250430140810.png --output-dir outputs
```

![実画像の入力と検出結果](examples/20250430140810_comparison.png)

| 処理 | 黒点候補 | 群候補 | R |
|---|---:|---:|---:|
| 提供された旧出力・旧検出関数の再実行 | 22 | 10 | 122 |
| 外縁マスク修正後 | 20 | 8 | 100 |

旧処理の2候補は、左右の太陽縁に沿う幅269px・高さ741/759pxの輪郭でした。輪郭全体は円周付近に達していても重心だけを判定すると採用されてしまいます。閾値処理後の内側マスクでこれらを除外しました。今回の20候補は正解ラベルで照合しておらず、検出精度や公式黒点数を意味しません。

入力画像 `20250430140810.png` は、作者（hirotonakakita）自身が撮影した太陽可視光画像です。解析例と比較画像はこの入力から生成しています。

## 処理

OpenCVで太陽円を検出 → CLAHE・シャープ化・平滑化 → 適応的閾値と面積条件で暗部候補を抽出 → 80pxの距離条件で群候補を作成 → `R = 10g + s`を計算します。

閾値は旧版を引き継いでおり画像解像度に依存します。本影と半暗部の厳密な識別、Zürich分類、公式の国際黒点数への較正は実装していません。群分けは起点からの距離で判定する旧方式で、連鎖的な近接点を統合しません。結果は目視確認を前提とします。

## 機械学習

ResNet18の画像特徴512次元と、群数・黒点数・相対数の数値特徴64次元を結合し、M発生・X発生・M回数を出力します。添付されたPyTorch学習コードはRGB画像のToTensorのみを使用し、数値は標準化済みCSV列を読み込んでいました。

既存モデルの利用は任意です。

```sh
python -m pip install -e '.[ml]'
solar-insight sample_data/synthetic_sun.png --checkpoint /path/to/flare_model.pth --scaler config/legacy_scaler_recovered.json --allow-legacy-preprocessing
```

合成画像での推論値には天文学的意味はありません。重みは同梱していません。安全な重み読込と厳密な構造チェックを行いますが、今回CPU環境（torch 2.14.0+cpu / torchvision 0.29.0+cpu）でモデル構造の厳密一致と実画像1枚の推論を確認しました。これはモデルの予測性能や元環境の再現を保証しません。復元した標準化はCSVの生値・変換値の対から求めたもので、重み作成時に使われたパラメータだとは確認できていません。出力は未較正のモデルスコアとして表示します。

## 検証と課題

- 合成画像の既知の黒点候補・群数、空画像のエラー、旧群分け方式をテストします。
- 今回の重みと構造が一致する既存の `train.py` は全件で学習し、ログのX Recall最大0.2609も学習中のデータで算出しています。未知データの精度としては記載しません。
- 研究全体では複数のモデルを試しています。初期の簡易モデルには50:50、別の画像モデルには80:20の分割コードがあります。過去の会話には日付で分ける再構築案も残りますが、今回の重みとの対応は未確認です。研究全体を一律に「分割なし」とは扱いません。
- 再学習を複数回試みましたが改善には至りませんでした。学習指標が一定値に張り付いたとの本人の記憶がありますが、該当指標と原因は未特定で、過学習とは断定しません。
- 学習用の天文台画像とSeestar画像を近づける明度・周辺の暗さの調整を本人が求めました。残存コードのCLAHEは検出用、明度調整は表示用で、元RGB画像を入力する推論経路には適用されていません。専用の周辺減光補正は確認できていません。
- 設計上は撮影後24時間以内のM/Xフレア発生を想定していましたが、厳密な時間窓は定義していませんでした。既存モデルは同日の太陽画像とフレア観測結果を対応させて学習しています。そのため、撮影前のフレアを正解に含む可能性があり、厳密な24時間先予測を学習・検証したものではありません。将来予測には、撮影時刻以降24時間のイベントで正解を作り直し、日付で分離したデータで再学習・評価する必要があります。
- 日付で学習・検証・テストを分け、標準化を学習期間のみで推定し、適合率・再現率・PR-AUC・混同行列で再評価することが次の課題です。
- 自作画像から抽出した数値と、学習CSVの公的観測値が同じ意味・分布かも未検証です。

## 出典と開発への関与

元プロジェクトでは自作撮影画像、NAOJ可視光画像・黒点情報、NOAA/GOESのフレア情報などを扱っています。提供された実観測サンプル1枚を同梱しています。大量の画像・元データセット・学習済み重みは含めていません。再配布条件と出典はデータ単位で確認します。

### 本人とGPTの担当

| 担当 | 内容 |
|---|---|
| 本人 | 論文調査、観測目的、M/Xの対象選択、約10年のデータ期間、画像とフレア記録の同日対応、画像と黒点数・群数・Rを組み合わせる方針 |
| 本人 | Seestar撮影・手動スタッキング、検出画像の目視確認、天文台画像との比較、GPTへの改善指示、実観測での出力確認 |
| GPT | 全コードの生成、モデル構成・学習方法・Xクラス重み設定などの提案。本人は機械学習の実装・設定を任せた |
| GPTを使った今回の整理 | CLI化、外縁マスク修正、安全な重み読込、テスト・説明文の整備 |

本人は、投影によって太陽中心と外縁でピクセル間隔の意味が変わることを考え、太陽面座標と球面上の中心角による群分けを構想しました。P角・画像方位を扱う処理も、その座標変換と将来の時間変化の解析を見据えて求めました。天文台の参照画像との比較を通じ、方位計算の調整をGPTに指示しましたが、誤差や計算式の妥当性の定量評価は未確認です。

天文台CSVのRとの差でCLAHEとシャープ化の16条件を4日分の画像上で比較する `optimize_parameters.py` も残っています。ただし実行や最適条件の採用の記憶・記録は確認できておらず、数値較正の実績とは扱いません。

現在の80pxという群分け条件はGPTの提案を採用したものです。太陽面座標に基づく角距離での群分けは未実現の構想です。座標変換にはP角だけでなく、太陽円の中心・半径、画像の回転・反転やB0角（円盤中心の太陽面緯度）などの確認も必要です。

Rの算出は現在の整理版でも実行できます。P角・方位の処理は旧プロトタイプに含まれますが、計算・画像の向き・時刻系の妥当性を確認する必要があるため、現在の整理版CLIには移植していません。時間変化を扱う将来予測も、現段階で検証済みの機能としては扱っていません。

このように、作者が処理内容と発展方針を定め、GPTを使ってコードを生成したプロジェクトです。このリポジトリへの整理・修正・テスト作成にもGPTを使用しています。

## 既存重みの実行検証

提供された重みはモデル定義にstrict=Trueで読み込めました。復元標準化と実画像（20候補・8群・R=100）でX/Mスコアはともに1.0、M回数の生出力は約366.91でした。スコアの飽和と回数出力の妥当性は未解決です。学習時画像（768×768）とこの実画像の寸法・画質・数値特徴の分布、標準化の由来、同日ラベルとの対応を追加検証します。この実行結果を実用的予測として表示しません。
